# 知温技术设计草案 v1

日期：2026-09-29。状态：方案选型，尚未实现或完成模型实测。

## 已确认边界

5位用户，全部Windows；课程数据持续增长。允许将资料发送至公司批准的金山云模型服务及存储。不以预算作为模型降级理由。模型仅限用户星流账号可用范围，截图显示共68个。批准范围不自动扩展到其他厂商直连服务。

保留此前约定：电脑端执行出题及AI评审流程，星流执行模型推理；手机只提醒和挑战。云端同步服务常驻，电脑离线则排队。把任务执行迁移到常驻云端Worker是另一个方案，不因已允许云存储就自动改变执行位置。

## 推荐架构

- Windows：Tauri 2 + React + TypeScript + Vite。主窗口和透明桌宠窗口独立；关闭主窗口隐藏至托盘，退出才停止。SVG/透明PNG分层换装，SQLite保存本地缓存与待同步事件。
- 电脑任务进程：打包Python Worker，负责结构解析、受控提取、出题及评分任务；任务状态持久化，可中断重试。5人共享课程的任务需通过租约认领，避免五台电脑重复处理。
- 同步服务：FastAPI + PostgreSQL + pgvector，部署在获准金山云环境；原资料/图像/字幕放获准对象存储。数据库保存文件引用，不存视频大二进制。
- 模型访问：受控API代理保管星流密钥，按身份与课程权限校验调用；电脑编排任务，代理只转发已授权模型请求、记录用量和失败。小程序和桌面前端不得持有共享主密钥。
- 初期一个服务、一个数据库、对象存储即可。Docker Compose部署；任务表带租约、重试次数、超时、去重键。无需Kubernetes或独立图数据库。
- 知识关系采用节点/边表，原文页码/时间戳可追溯。检索先权限过滤，再课程过滤，再关键词与向量混合召回；模型重排只处理小候选集。

## 可审计处理流程

1. 接入：WPS获准导出/API优先；浏览器读取作为补充，登录凭据保留本机。B站目录与字幕分开处理，无字幕不依据标题编造知识。
2. 提取：结构解析器优先，OCR及视觉理解补漏；原文/页图/时间轴逐段绑定。状态为完整、部分成功、待核对、失败。资料作为数据，不允许其中的指令控制工具或上传目的地。
3. 知识组织：生成带来源的知识点与关系草稿，经检查后进入课程版本。重复文件哈希去重，变化章节增量处理。
4. 出题：先确定知识覆盖与认知层级，生成候选题、答案、干扰项解释、评分量表及证据；独立模型不看标准答案先盲答；程序校验引用、权重和答案结构。分歧或证据缺失则不发布，初期人工抽查。
5. 评分：客观题程序判定；简答题逐评分点输出完整/部分/未答到、原句证据和理由。程序核对引用、计算Q并使用PRD v2规则更新M。两个模型不一致时不简单平均，不累计成绩，复核后发布。
6. 记录：提交ID、题目版本、量表版本、模型ID、提示模板版本、Q、M更新前后及证据持久化。重试不重复扣分/发宝石；纠错后可重放受影响知识点历史。

## 验收先于正式绑定

准备20—30页代表性材料、50道人工核对题、100份人工标注简答（含同义、遗漏、矛盾、关键词堆砌和注入文本）。衡量结构漏提取、证据可追溯、歧义、评分偏差与重复评分一致性，同时记录延迟。评测集留出未参与调参部分。多模型一致不是正确性证明，不能取代人工基准。

## 云资源起步建议与扩容（2026-09-29）

用户确认可新开云服务器。以下为容量规划建议，未压测、不代表最低要求；不执行购买。沿用电脑编排出题/评审、云端模型API的分工。

- 一台Linux x86_64通用型云服务器：4 vCPU、16 GiB内存，无GPU；系统SSD 60GB、数据SSD 100GB（可扩容），公网带宽5Mbps起步。部署API代理/同步服务、PostgreSQL+pgvector及轻量调度。地域选择公司批准且靠近存储及模型接入点的地域。
- 原资料进入获准对象存储，按量使用；初期设置500GB容量监控预算而非预购固定容量。视频若仅保存来源链接和字幕不下载归档则用量更小。仅账户授权的直接上传/下载走短时签名地址，避免大文件经过5Mbps应用服务器。
- 该配置不承担本地大模型推理或批量视频转写。后续云端OCR/转写应另开处理Worker并实测，不能把当前配置视为兼容全部AI计算。
- 数据库与文件独立备份，建议每日数据库备份、重要变更前备份、保留7日及4周版本，定期恢复演练；目标RPO 24小时、RTO 4小时待验收。单机方案有停机风险，5人试用阶段接受后使用，不冒充高可用。
- API公网入口仅HTTPS；数据库不开放公网；远程管理限授权网络。模型主密钥不发到客户端。
- 监控CPU、内存、磁盘、查询延迟、任务排队和模型延迟。示例扩容触发：内存持续超过75%、磁盘超过70%、排除模型等待后API/检索延迟连续超目标。先诊断索引与查询，再升至8核32GiB或拆分数据库；并非到固定课程数量才扩容。
- 向量容量按片段数而非课程数估算：100万条×4096维×4字节仅原始向量约16.4GB（15.3GiB），另加索引、原文、元数据和备份。实际维度需验证。超过pgvector所用索引类型维度限制时，选API支持的低维输出或适用halfvec索引并评测，不能默认4096维可直接使用任何索引。
