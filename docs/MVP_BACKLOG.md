# 首版开发任务与验收清单

本清单从 [PRD](PRD.md) 派生。PRD 是产品规则来源；本文件负责把工作拆成可执行交付。当前仅完成需求文档，下面所有实现任务均未完成。

## A. 开工默认与完成定义

- 默认 Windows、单用户、一章 15—30 个知识点、公开或已获准资料。
- 默认本地数据库与文件；网页界面先跑通，再封装桌面。
- 默认一个可用模型端点，三个逻辑 Agent，不建三套服务。
- 不先开发桌宠、社交、多端同步、实验判分或客户场景。
- 任一任务完成需有运行结果或测试证据；模型 mock 只能证明流程，不证明内容质量。
- 在 README 记录启动、配置、测试、备份恢复方法；配置示例不得包含密钥。

## B. 建议代码边界

```text
apps/
  desktop/                  # 桌面窗口、托盘、通知、sidecar
  web/                      # 课程、作答、反馈、成长界面
services/
  backend/
    api/                    # 请求校验与响应
    domain/                 # 评分、掌握状态、奖励、调度纯规则
    workflows/              # 导入、出题、评分、复核编排
    agents/                 # A/B/C 提示与结果 schema
    providers/              # 模型适配、数据路由、超时
    ingestion/              # 各格式解析与出处定位
    storage/                # 数据库、文件、备份、迁移
    jobs/                   # 持久化后台任务
tests/
  unit/                     # 规则与时钟
  integration/              # 数据库、接口、任务恢复
  model_eval/               # 标注样本、质量评估
  desktop/                  # 系统集成验收记录
fixtures/                   # 可分发的公开/合成示例，注明来源
docs/
```

这是目录建议，不需要预先创建空模块。用户资料和模型密钥不能进入版本仓库。

## C. 按依赖顺序执行

### M0：固定内容的纵向闭环

- [ ] T01 建立前后端开发环境与最小启动入口。
  - 前端能访问健康检查；开发配置与生产配置分开。
  - 健康响应区分“后端可用”与“模型可用”。
- [ ] T02 建立数据库迁移和一章固定内容。
  - 保存课程、课节、知识、题目版本和来源定位。
  - 有公开/合成示例；演示数据标识清楚。
- [ ] T03 实现题目发布校验。
  - 缺来源、缺目标、权重和不是 100 时拒绝发布。
  - 不允许修改已发布题目版本。
- [ ] T04 实现创建会话、展示题目和提交回答。
  - 前端题目响应不含隐藏答案或 rubric。
  - 回答先落库；submission_id 可重试但不重复写。
- [ ] T05 实现固定评分接口与反馈页面。
  - 客观评分可真实运行；简答使用测试桩时明确标识。
  - 支持“不知道”、跳过、提示和待评价状态。

验收：同一用户能完成一节课的回忆，并在重启后看到答案记录。对应 PRD AC01、AC02、AC11 的相关部分。

### M1：评分、记忆与奖励规则

- [ ] T06 实现要点计算、核心错误封顶与独立性。
  - 权重乘 0/0.5/1，由后端算分。
  - 无法评价与答错分离。
  - 看答案后重答不能伪装独立。
- [ ] T07 实现 ExposureEvent 与三维证据。
  - 正确处理材料查看、提示、解析和产品外复习自报。
  - 回答前的间隔与反馈后的新接触顺序正确。
  - 单选识别证据不升级自主回忆。
- [ ] T08 实现调度与可控时钟。
  - 示例成功链为第 1/4/11/25/55 天。
  - 暂停、休息日、提前练习、失败与无任务可测试。
  - 用户时区改变不破坏 UTC 事件时间。
- [ ] T09 实现证据等级与行动状态。
  - “已巩固且待复习”可同时存在。
  - 新错误保留历史、标记待修复。
  - 不适用维度不计为薄弱项。
- [ ] T10 实现成长账本与有效学习日。
  - 同知识点同日取最高档、只补差额。
  - 无单纯签到奖励；重复题不可刷积分。
  - 当前周目标不因当周修改追溯变化。
- [ ] T11 实现申诉状态和影响重算。
  - 评价冻结后停止其有效影响。
  - 新评价替代旧评价，账本追加补偿。
  - 整题撤回能定位所有受影响的作答。

验收：PRD AC03—AC13 的规则与事务测试通过。真实跨天效果尚需后续试点，模拟时钟只用于测试代码。

### M2：知识摄取和三个 Agent

- [ ] T12 实现来源导入与状态机。
  - TXT/Markdown、文本 PDF、SRT/VTT、链接收藏。
  - 文件哈希去重、保留原件、定位页码或时间戳。
  - 不支持的格式明确报错，不把空解析当成功。
- [ ] T13 实现 A 的知识提取与候选关系。
  - 每条知识都有原文引用和适用范围。
  - 同名概念不自动合并；冲突可隔离。
  - 个人记录不能直接成为公共答案。
- [ ] T14 实现 B 的课节与题目准备。
  - 沿用已确认课程目录。
  - 一次处理一个小单元；先评分要点后题干。
  - 有题族、主要目标与维度、难度、预计时长。
- [ ] T15 实现 C 的发布审核和作答评审。
  - 检查已教范围、可答性、引用支持和合理替代表达。
  - 标注自动审查与实际专家审核的区别。
  - 不确定可返回待复核。
- [ ] T16 实现模型适配器和路由。
  - schema、取消、超时、用量与版本记录。
  - 内部资料不能自动回退到未授权模型。
  - 同一提供方可被 A/B/C 复用。
- [ ] T17 实现持久化工作流。
  - 网络失败有限重试；语义失败最多两轮修订。
  - 重启后恢复；重复执行不重复发布或记账。
  - 已发布题优先复用，在线学习不等待整个入库链路。
- [ ] T18 建立最小模型评估集。
  - 至少 20 道审核题、40 份标注回答，记录标注者与依据。
  - 覆盖正确同义、部分正确、核心错误和歧义。
  - 报告误判合格、误判不合格、待复核与样本数。

验收：PRD AC01—AC04、AC14、AC15、AC18、AC19；不能仅凭 schema 校验宣称题目质量合格。

### M3：桌面与数据可靠性

- [ ] T19 接入桌面外壳和后端进程管理。
  - 单实例、启动握手、关闭到托盘、彻底退出。
  - 本地 API 只绑定 loopback，设置访问令牌和来源限制。
  - 密钥使用系统凭据存储，不进入前端或普通日志。
- [ ] T20 实现提醒与回归体验。
  - 用户可选自启；设置提醒窗口、暂停、稍后。
  - 每日最多一次主动提醒，无任务不推。
  - 休眠后不补发通知；中断回归最多三题。
- [ ] T21 实现一致性备份恢复。
  - 导出数据库快照、附件清单、校验值及 schema 版本。
  - 不导出密钥；恢复前校验并保留当前备份。
  - 损坏包、缺附件、版本不兼容都能给出清楚结果。
- [ ] T22 完成成长页面和低门槛沉淀。
  - 三维证据、真实前后回答、单一成长积分、周目标。
  - 一句疑问/mentor 纠正可保存并手工关联。
  - 表扬有依据，不展示虚构能力百分比。
- [ ] T23 完成 Windows 安装与真实环境验收。
  - 实测启动、关窗、退出、休眠、升级及备份恢复。
  - 卸载不静默删除个人学习数据。

验收：PRD AC16、AC17、AC20 以及主流程键盘可用性；记录测试电脑、模型和耗时。

### M4：自用与小范围试点

- [ ] T24 自己使用真实课程一章，记录摩擦点与误判。
- [ ] T25 条件允许时邀请约 3—5 位目标用户，持续两到三周。
- [ ] T26 收集延迟作答、再次培训使用、负担与提醒关闭情况。
- [ ] T27 修正内容、评分和负担问题，决定是否进入 P1。
- [ ] T28 准备比赛演示与说明；模拟日期与预置反馈明确标注。

不要以“用户打开过几次”作为通过试点的唯一依据。若用户觉得像额外作业，优先减少准备和作答成本；若评分不可信，先修评分，不增加奖励。

## D. 最小发布核对

- [ ] 最新定位与范围没有混入操作、客户模拟或老员工调研。
- [ ] 素材来源、内容版本、题目版本与评分规则可追溯。
- [ ] 规则测试、事务测试、恢复测试与桌面测试有记录。
- [ ] 模型评分有真实样本评估；不足时显式限制发布能力。
- [ ] 提示、重新作答和近期重读不会伪造延迟记忆。
- [ ] 评分失败或题目申诉不会使用户丢答案或被错误扣分。
- [ ] 接口不会向前端提前返回答案，不会泄露密钥。
- [ ] 退出、暂停、关闭提醒、导出和恢复都能找到并使用。
- [ ] 没有虚构科学效果、记忆概率或专家背书。
- [ ] README 说明实际已实现能力与剩余限制。

## E. 后续需求入口

完成 M4 后再逐项评估：更丰富资料解析、材料内问答、工作文档自动关联、受控联网补缺、徽章、桌宠、同步与团队课程分发。每项都应回答“它减少了哪种学习负担或改善了哪种记忆证据”，不能只因可实现而加入。
